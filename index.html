01

Foundation

Start with a clear destination.

  • Define the outcome. Say what you want to build, who it is for, and what “done” looks like.
  • Give useful context. Include the relevant files, constraints, and an example of the result you expect.
  • Work in small steps. Review one meaningful change before moving to the next.
02

Environment

A good workspace does half the explaining.

  • Open the right folder. Keep the source files and project instructions together.
  • Make the setup repeatable. Document how to run the project and check a change.
  • Keep secrets out. Use environment variables for credentials; never paste them into prompts or commit them.
03

Git

Build with a way back.

  • Read the diff. Know what changed before you accept or commit it.
  • Create useful checkpoints. Make small, focused commits with messages that explain the change.
  • Isolate parallel work. Use branches or worktrees when different tasks need their own space.
04

Models and tokens

Spend attention where it matters.

  • Match effort to the task. Give difficult reasoning more room; keep routine changes focused.
  • Curate the context. Share the files and details that help the task, without unrelated history.
  • Leave a clear handoff. Record decisions, progress, and next steps before starting a fresh conversation.
05

Control and skills

Make your way of working repeatable.

  • Write an AGENTS.md. Capture the project’s conventions, constraints, and verification steps.
  • Set clear boundaries. Specify what can change and which decisions need your approval.
  • Package repeatable work. Turn a useful process into a focused skill with clear inputs and a checkable result.
06

Tools and scale

More reach. The same standard.

  • Connect tools with a purpose. Add access when a task needs it, and keep permissions scoped.
  • Delegate bounded tasks. Give each parallel task a clear goal, ownership, and expected output.
  • Verify the result. Run the relevant checks, inspect the work, and confirm it meets the original brief.
